# minipi 隐私说明

**一句话：你的数据留在你的电脑上。我们不收集任何东西。**

这份说明里的每一条都对应代码里的实际行为，不是公关文案。有疑问可以对照 `src/main/` 下的源码核实。

---

## 一、数据存在哪

全部在 `~/.minipi/`（Windows 上是 `C:\Users\<你>\.minipi\`）：

| 文件 / 目录 | 内容 |
|---|---|
| `settings.json` | 主题、场景、窗口位置、模型偏好等设置 |
| `credentials.json` | 你填的 API Key（文件权限 `0600`，仅当前用户可读） |
| `providers.json` | 自定义提供方定义（地址、协议、模型清单） |
| `sessions/` | 会话正文（JSONL）与元数据索引 |
| `outbox/` | 你说「导出 / 另存为」时生成的文件 |
| `approvals-audit.log` | 审批记录：哪个文件在什么时候被允许写入了 |
| `logs/` | 运行日志 |

**这些文件不上传到任何地方。** 我们也没有能接收它们的服务器。

---

## 二、什么情况下会联网

只有三种，全部由你的操作触发：

1. **你发消息时** —— minipi 把你的提问和上下文发到**你自己配置的那个模型 API 地址**。请求直接发往该地址，不经过 minipi 的中转。至于那个服务商怎么处理你的数据，取决于它的隐私政策，不取决于我们。
2. **你点「联网搜索」时** —— 走 DeepSeek 的搜索接口，用的是**你自己填的 DeepSeek Key**。
3. **你点「拉取模型」时** —— 向该提供方的 API 请求一次模型清单。

除此之外没有任何后台请求：不检查更新、不报崩溃、不埋点。

---

## 三、我们不做什么

- **不收集遥测。** 没有统计 SDK，没有匿名使用数据上报。
- **不做崩溃上报。** 程序崩了，信息只写进本地 `logs/main.log`。要不要发给我们，由你决定。
- **不内置第三方分析。** 没有 Google Analytics、没有 Sentry、没有友盟。
- **不在你不知情时读你的屏幕。** `Alt+Shift+Space` 抓选区只在**你按下这个键**时发生一次，抓的是你当时选中的内容，抓完直接作为提问内容。不截图、不持续监听。
- **不替你写文件。** 需要写文件时会弹审批卡，只有你点了「允许」，才会写入，且只写你打开的那一个文件。

---

## 四、API Key 怎么处理

- **只写不读**：存进去之后，界面上**不会回显**已保存的 key。你看到的是一个占位状态，不是 `sk-****` 打码后的真值。
- **不回传渲染层**：key 只在主进程里被读取使用，页面脚本拿不到它。
- **不进日志**：所有错误信息和日志都会先过一道脱敏处理，key 会被替换掉。
- **不进 `providers.json`**：提供方定义文件里明确拒绝 `apiKey` / `key` / `token` 这类字段，密钥只走 `credentials.json`。

---

## 五、你可以自己做这些事

- **看**：`~/.minipi/` 下全是纯文本（JSON / JSONL），用记事本就能看。
- **删**：删掉任意会话文件即可，索引会在下次启动时自动对账。
- **搬**：整个 `~/.minipi/` 拷到另一台机器，会话和设置都在。
- **彻底清除**：删掉整个 `~/.minipi/` 目录。卸载程序**不会**替你删（删除用户数据属于数据丢失，不属于清理）。

---

## 六、如果将来要变

如果某个版本要加入任何形式的数据上报（比如可选的崩溃报告），会：

1. 在这份文档里写明**具体上报什么字段**；
2. 默认**关闭**，由你主动开启；
3. 开启前弹一次说明。

在此之前，上面写的「不收集」就是字面意思。
