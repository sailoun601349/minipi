# 04 · 交互与状态规范（冷调仪器面板）

> **定位**：本文件是 minipi **前端层**的长期执行规范 —— 回答「一个状态出现时，前端必须显示什么、用户能做什么、下一步去哪」。
> **不回答**：像素长什么样（见 `03-组件规格.md`）、颜色取什么值（见 `02-令牌规格.md`）、审批闸门怎么实现（见 `docs/minipi-approval-gate-design.md`）。
> **写法约束**：凡是给出具体数值（px / 对比度 / 时长 / 上限）的，一律来自 `02-令牌规格.md`、`03-组件规格.md`、`docs/minipi-approval-gate-design.md` 或 `src/shared/protocol.js` 的**已落地实测值**；没有实测依据的地方，本文件**不写数字**，只写规则。
> **给谁看**：加新功能的前端开发者。做之前读 §1 交互原则，落地时对照 §2 状态机清单与 §8 自查清单。
> **配套文档**：`ui-optimization/future-ui/01-视觉方向.md`（方向）· `02-令牌规格.md`（令牌）· `03-组件规格.md`（组件）· `04-落地映射.md`（施工图）· `docs/minipi-approval-gate-design.md`（审批数据契约）· `docs/minipi-ui-refresh-spec.md`（界面改造需求）。

## 0. 三个必须先分清的概念

minipi 里有三组**极易被混用**的概念。前端代码里它们的名字也是三组，历史上已经撞过一次车（`data-scene`）。

| 组 | 概念 | 取值 | 前端属性名 | 说明 |
|---|---|---|---|---|
| A | **窗口形态**（shell） | `ball` / `mini` / `full` | `body[data-mode]` | 一个窗口实例的三态形变（48×48 → 360×480 → 960×680） |
| B | **场景**（scene） | `chat` / `work` | `data-scene` | 产品能力档位：会话+导出 / 本地文档 |
| C | **模型/连接状态** | `idle` / `streaming` / `error` | `store.conn` / `turn.status` | 运行态 |

> **命名红线**：形态属性**只能叫** `data-mode`，**不得叫** `data-scene`。`data-scene` 已被「会话 / 文档」占用（`src/renderer/index.html:1557` 的 `role="group"` 切换器），复用会造成两个概念在同一属性上打架（`04-落地映射.md` §5 已标红）。
> **用户可见名**：形态对用户说「悬浮球 / 小窗 / 大窗」；场景对用户说「会话 / 文档」（`SCENE_UI`：`chat → 会话`、`work → 文档`）。**`chat` / `work` 这两个英文 id 不出现在任何用户可见文案里**。

## 1. 交互原则（7 条）

> 每条格式固定为「**原则 → 为什么 → 落地判据 → 反例**」。
> **判据是可机械检查的**：能写成 `grep` / `qa-*.mjs` 断言的，就写成断言；不能机械化的，写成「人工评审项」并标注。

### 1.1 零死入口

- **原则**：任何可点元素，点下去必须产生**可见结果** —— 状态变化、界面出现、或一条明确的「此路不通」提示。三者都没有 = 死入口，禁止出现。
- **为什么**：minipi 是常驻工具，用户随时可能误点。一个"点了没反应"的按钮会直接损失信任，且用户无法区分"没生效"和"坏了"。
- **落地判据**：
  1. 渲染层每一个 `<button>` / 可点击 `[data-*]` 都必须绑定处理函数；人工评审项：grep 每个 `data-*` 动作属性，确认有对应 handler。
  2. 任何异步 handler 的失败分支**必须**给用户一条反馈（toast / 内联提示），不能只 `catch {}`（现状 `doAbort` 里 `catch(() => {})` 属允许例外：中断是幂等动作，已有本地状态反馈）。
  3. 无后端能力的入口**不画**（`docs/minipi-ui-refresh-spec.md` §2 原则 4「不做假按钮」）。
- **反例**：画一个「导出 PPT」按钮但只弹 toast「暂不支持」—— 这不是死入口，但仍是假入口。正确做法是不画。

### 1.2 每一次交互都有反馈

- **原则**：任何可交互元素必须有**可见的** hover / focus / active 三态反馈；三者缺一即为不合格。
- **为什么**：产品是「冷调仪器面板」—— 靠**明度与秩序**表达可交互性，不靠色彩。没有反馈 = 用户不知道哪里能点。
- **落地判据**：
  1. 所有可交互元素必须命中 `03-组件规格.md` §7 的像素手法：hover 只改 `border-color` / `background` / `box-shadow(inset)`，**禁止 `transform: scale()`**（`audit.mjs` §2 判 FAIL）。
  2. 焦点环统一 `outline:2px solid var(--accent)`（`03-组件规格.md` §7）；`outline-offset` 取 **1px**（`03-组件规格.md` 裁剪坑 11：取 2px 会让贴边小按钮的焦点环被裁掉一半）。
  3. `:focus-visible` 是唯一焦点环来源；**禁止**给 `textarea` / `input` 写 `outline:none` 而不自绘（裁剪坑 7）。
- **反例**：`.iconbtn` 只有 `:hover` 没有 `:focus-visible` → 键盘用户完全看不见自己在哪。

### 1.3 状态必须可见，且只出现一次

- **原则**：一个事实**只由一个载体表达**。同一状态不得同时用 chip + 边框 + 文案三处重复标注。
- **为什么**：三态球只有 48×48，多一个红点就溢出窗口矩形（裁剪坑 3）。重复标注在小尺寸下会互相打架，在大尺寸下会让人怀疑哪个是真的。
- **落地判据**：
  1. 状态色**只允许**出现在三类载体上：**2px 语义边 / chip 底 / 状态文字**（`03-组件规格.md` §6）。禁止整块状态色背景（彩色面积会爆表）。
  2. 球的状态由 `data-ball` 属性**单点**决定：`.ball__badge` / `::after` / 徽标都是它的从属表现，不另设独立开关。
  3. 审批卡的倒计时与超时提示是**同一事实的两个阶段**，超时后必须由「倒计时」切换为「已超时，已拒绝」，不得并存。
- **反例**：球上既有 unread 红点、又有 "有新产出" 文字气泡 —— 48px 放不下，且两个都可能过期。

### 1.4 异步必有进行中态

- **原则**：任何耗时操作必须在**原地**显示进行中状态，并说明「正在做什么」。
- **为什么**：minipi 的定位是「5 秒通道」（审批设计 §4.2）。用户等不起一个没有反馈的按钮。
- **落地判据**：
  1. 耗时操作（导出、模型生成、审批提交、连接）必须有**进行中态**，且进行中态必须**占用原控件位**（同位切换），不允许"按钮还在、另处冒个转圈"。
  2. 进行中态**必须可中断或可解释**：要么给出取消入口，要么明说不能取消（如「导出全程后台」）。
  3. 禁止用整块骨架屏遮住已有内容（用户会以为内容丢了）；骨架只用于**尚无内容**的空列表。
- **反例**：导出时按钮照常可点，用户连点三次触发三次导出。

### 1.5 失败必须给"下一步"，而不是只给结论

- **原则**：任何失败反馈 = **发生了什么 + 现在能做什么**。只写"失败"的错误文案不合格。
- **为什么**：错误态是用户唯一需要产品"说话"的时刻。只说"失败了"等于把问题推回给用户。
- **落地判据**：
  1. 错误文案结构固定为「**结论句 + 下一步动作**」两段（§4.3 给了公式）。
  2. 可重试的错误必须给出**可点的重试入口**（重试按钮或"点此重试"的文字动作）。
  3. 错误文案**不得出现**任何密钥、内部绝对路径、堆栈、IPC 通道名（§4.4）。
  4. 原始技术细节**折进 `<details>` 默认收起**（现状 `buildConnError` 已如此，是正确样板），不外露在正文。
- **反例**：`toast('提交审批失败：' + parsed.detail, 'err')` —— 把内部 detail 直接甩给用户，且没有重试入口。

### 1.6 破坏性动作可逆、可预览

- **原则**：任何会改用户文件、终止运行、丢弃数据的动作，必须**先可预览、再可确认、错了可退**。
- **为什么**：work 场景的铁律是"只改用户显式打开/新建的那一个文件"。UI 层是这条铁律的**唯一用户可见部分**。
- **落地判据**：
  1. 审批卡必须展示**真实变更内容**（`edit` 给真实 diff、`write` 给预览），不给"只有文件名"的空卡（审批设计 §3.3 验收锚点）。
  2. 覆盖已有文件必须**重警示**（`overwrite:true` ⇒ 明确标注会覆盖）。
  3. 「终止本轮」与「拒绝」是**两个不同的按钮**，不得合并成一个"取消"（语义不同：`deny` = 这条不行换办法，`terminate` = 整轮停）。
  4. 删除类动作走二次确认（`docs/minipi-ui-refresh-spec.md` §6.2 规则 2）。
- **反例**：一个「确定要覆盖吗？」的 confirm 弹窗，但不展示将被写入的内容 —— 用户是在盲确认。

### 1.7 尊重"可逆"与"自动"的分界

- **原则**：**可逆**的操作可以自动发生并提示；**不可逆**的操作必须由用户显式触发。
- **为什么**：自动做的事一旦错了，用户要有路回来；没有路回来的事（覆盖文件、终止整轮）必须由人按。
- **落地判据**：
  1. 不可逆动作的按钮**必须带确认或后果说明**（tooltip / 卡内说明 / 二次确认）。
  2. 自动行为（自动折叠、自动置顶、自动切场景）必须**可撤销**，或至少有明确告知。
  3. 一切"记住"类开关（记忆类设置）默认**关**，且作用域必须写在控件旁（§5.4）。
- **反例**：切场景直接清空当前会话流而无确认 —— 现状已修（`minipi-ui-refresh-spec.md` §UX-01），保持。

## 2. 状态机清单

> **读法**：每一行是一个**必须能独立判定的状态**。「是否可中断」= 用户/系统能否在状态未终结前把它拉出来。「出口」= 它接下来能去哪些状态。
> **铁律**：一个状态如果"看起来像另一个状态"，合并；一个状态如果"需要第二处表达"，拆开。

### 2.1 窗口形态（3 态）

| 状态 | 触发条件 | 视觉表现 | 是否可中断 | 出口 |
|---|---|---|---|---|
| `ball`（悬浮球 48×48） | 初始态；小窗点「收起回球」；大窗点「收起为小窗」 | 球体四层光影 + π；`data-mode="ball"` | 是 —— 拖拽 / 右键菜单 / 单击展开 | `mini` |
| `mini`（小窗 360×480） | 球单击 / 大窗收起 | 36px 头部 + 消息流 + 三行输入区；`data-mode="mini"` | 是 —— 头部「放大为大窗」/「收起回球」 | `ball` / `full` |
| `full`（大窗 960×680） | 小窗「放大为大窗」/ 球右键菜单「打开大窗」 | 46px 头部 + 三栏（会话 208 / 对话 / 抽屉 264）；`data-mode="full"` | 是 —— 头部「收起为小窗」 | `mini` |

> **形态切换的三条规则**：
> 1. **形态切换不重建会话**：同一 `sessionId` 一路带下去（`docs/minipi-ui-refresh-spec.md` §4.1）。
> 2. **形态切换不重绘聊天流**：`renderViews()` 只在结构变化时跑（`src/renderer/index.html:3915` 附近的既有约定）。
> 3. 右键菜单**不是第四形态**：它是 ball 态的一次临时窗口扩张（`BALL_MENU_SIZE` = 200×262，收起后还原 48×48）。

### 2.2 球的状态（4 态）

| 状态 | 触发条件 | 视觉表现 | 是否可中断 | 出口 |
|---|---|---|---|---|
| `idle`（空闲） | 无任务；回合落定且非 `done`；连接错误后复位 | 静态球 + π；`aria-label="minipi 悬浮球，当前状态：空闲"` | 是 —— 点击展开 | `thinking` / `await` / `unread` |
| `thinking`（思考中） | 提交 prompt 后**立刻**置位（不等首字） | 球内 2px 旋转开口环（`border-top-color: var(--accent)`，`animation:spin 1s linear infinite`） | 是 —— 用户点「中断」或按 `Esc` | `idle` / `unread` / `await` |
| `unread`（有产出） | 回合落定为 `done`（`setBall(t.status === 'done' ? 'unread' : 'idle')`） | 右上 11px 红点，`right:0;top:0`，2px `--bg` 描边（**不得** `right:-1px`） | 是 —— 展开小/大窗后自动清（`setBall(store.ball === 'unread' ? 'idle' : ...)`） | `idle` |
| `await`（待确认） | 有未决审批卡推来（`setBall('await')`） | 金色描边 `border-color: var(--warn)` + 右上 19px「!」徽标 | 是 —— 审批卡落地后自动复位 | `idle` |

> **关于"异常"球态**：当前实现**没有**独立的异常球态。失败**不占用球**，而是通过消息流的 `error` chip（`chip--danger`「失败」）+ 连接错误卡表达；球保持 `idle`。
> **为什么这样设计**：48×48 窗口里塞不下第四种标记语汇；且"失败"是**某条消息**的属性，不是**这个助手**的属性 —— 把它画在球上会让用户误以为整个应用坏了。后续若要加异常球态，须先在 `03-组件规格.md` §1.3 的状态表里立行，并遵守裁剪坑 3（不得溢出）。
> **减弱动效下的降级**（`prefers-reduced-motion: reduce`）：`thinking` 环**停在静态 1/4 弧**（渐变仍在，颜色不退回静态灰），`await` 徽标停在静态金色。**状态可读性不得因关动效而丢失**。

### 2.3 消息流状态（4 态）

| 状态 | 触发条件 | 视觉表现 | 是否可中断 | 出口 |
|---|---|---|---|---|
| `streaming`（生成中） | 收到首个 delta | 消息轴点光晕（`--fx-glow-accent`）；正文逐段追加；底部「停止」按钮启用，提示行改 `Esc 中断 · Enter 排队` | 是 —— 「中断」按钮 / `Esc` | `done` / `aborted` / `error` |
| `done`（已完成） | 回合落定且无错误 | 正文完整；头部无状态 chip；球转 `unread` | 否（终态） | — |
| `aborted`（已撤销） | 用户点「中断」或按 `Esc` | 头部 `chip--warn`「已中断」；正文保留已生成部分 | 否（终态） | — |
| `error`（失败） | 事件流 `error` / 连接失败 | 头部 `chip--danger`「失败」；正文给出结论 + 下一步 | 否（终态，但可重试发起新轮） | — |

> **「中断」的迟到尾巴护栏**：用户中断后立刻发新消息，旧回合的 `agent_settled` 可能迟到 —— 现状用 `abortSettleGate` 吃掉第一个 settle（`src/renderer/index.html:3020` 附近）。**新增任何"中止"路径时必须一并接入这个闸**，否则会出现"刚发的新消息立刻显示完成"。
> **中断后不得清空已生成的正文**：用户已经付过的等待成本要留在屏幕上。

### 2.4 审批卡状态（8 态）

| 状态 | 触发条件 | 视觉表现 | 是否可中断 | 出口 |
|---|---|---|---|---|
| `pending`（待决） | 主进程推 `phase:"push"` / `"update"` | 卡片左 2px `--warn` 边；标题「写入文件 / 修改文件 / 执行命令」；倒计时 `剩 N`；三/四档按钮 | 是 —— 用户点按钮 / 5 分钟超时 | `allowOnce` / `allowSession` / `denyWithInstruction` / `terminate` / `expired` |
| `deciding`（进行中） | 用户点下按钮后 | 卡片加 `.approval--deciding`（`opacity:.7`），**全部按钮 `disabled`**；**不乐观移除卡片** | 是 —— IPC 失败时复位按钮允许重试 | `resolved` / 回到 `pending`（IPC 失败） |
| `allowOnce`（允许一次） | 用户点「允许一次」 | toast「已允许这一次」；服务端回 `phase:"cancel"` 撤卡 | 否（终态） | 卡被撤回 |
| `allowSession`（本会话允许此文件） | 用户点「本会话允许此文件」且 `alwaysAllowEligible` | toast「已允许：本会话该工具不再询问」 | 否（终态） | 卡被撤回；后续同文件调用**不再弹卡** |
| `denyWithInstruction`（拒绝并说明） | 用户点「拒绝并说明」（可带 ≤500 字说明） | toast「已拒绝，并转达了你的说明」 | 否（终态） | 卡被撤回；说明**回灌给模型** |
| `terminate`（终止本轮） | 用户点「终止本轮」 | toast「已终止本轮」 | 否（终态） | 卡被撤回；**整轮 agent 运行停止** |
| `expired`（已超时已拒绝） | `createdAt + timeoutMs` 到点（`APPROVAL_TIMEOUT_MS = 300000`） | 卡片 `.approval--expired`（`opacity:.62`）；按钮全部禁用；追加文字「已超时，已拒绝」 | 否（终态） | 服务端撤卡；按「拒绝」处理 |
| `cancelled`（已撤回） | 服务端推 `phase:"cancel"` | 卡片从流中移除 | 否（终态） | — |

> **超时 = 默认拒绝**（fail-closed）。超时**只**对应 `deny`，**不会**产生 `terminate`（审批设计 §5.1）。
> **未决审批重启后一律丢弃，不恢复、不放行**（审批设计 §6.4）。渲染层**不得**在启动时把历史 pending 画成"可点的卡"。

### 2.5 导出 / 产出流程状态（4 态）

| 状态 | 触发条件 | 视觉表现 | 是否可中断 | 出口 |
|---|---|---|---|---|
| `idle`（占位/无） | 没有 `turn.pendingOutcome` | 导出按钮正常可点 | 是 | `generating` |
| `generating`（生成中） | `startExportRun()` 置 `pendingOutcome.phase='generating'` | **【规范要求，现状未实现】** 该轮次显示「正在整理文档」占位；同轮再次点导出 → toast「这条回答的文档还在整理，稍等片刻」（现状仅导出按钮 loading，**流内不插占位卡**，见 §9.1） | **否** —— 导出全程后台（2026-10-20 用户裁定已移除取消/重试按钮） | `success` / `failed` |
| `success`（成功） | 收到 `EVENTS.OUTCOME` | 产出卡：左 2px `--success` 边；格式 chip（docx 蓝 / md 紫）；`文件名 · 字节数 · 时间`；三个动作「打开 / 另存为 / 修订」 | 否（终态） | — |
| `failed`（失败） | `generateOutcome` reject 或抛错 | 清 `pendingOutcome`（导出钮恢复可点）+ toast `文档生成失败：<原因>`（`toast--err`） | 是 —— 可直接重试 | `generating` |

> **降级不是失败**：`degraded:true`（docx→md / JSON 失败 / 落盘失败）走 `success` 路径，但产出卡左 2px 边改 `--warn`、加降级 chip 说明「原定 docx，已降级为 Markdown —— 内容完整，格式从简」。**降级必须显式标注，不能静默换格式。**
> **落盘失败 ≠ 生成失败**：`broken` 时产出卡标题写「产出（未落盘）」，并给「复制内容」按钮兜底 —— 用户拿得到内容才算完。

### 2.6 面板与浮层状态（6 态）

| 状态 | 触发条件 | 视觉表现 | 是否可中断 | 出口 |
|---|---|---|---|---|
| `closed`（关闭） | 默认 | `hidden` 属性 + `display:none !important` | 是 | `open` |
| `opening`（打开中） | 点击触发 | 抽屉 `transform` + `opacity` 过渡（`03-组件规格.md` §3.3 取 `.18s ease`） | 是 | `open` |
| `open`（打开） | 浮层显示 | 抽屉：`data-open="true"`；浮层：`--shadow-2` + `inset 0 1px 0 var(--fx-lit-top)` | 是 —— `Esc` / 点外 / 再点触发器 | `closing` |
| `closing`（关闭中） | 触发关闭 | 过渡回 `opacity:0` / 移出 | 是 | `closed` |
| `focus-trapped`（焦点陷阱内） | 浮层为模态（设置面板 / 确认条） | **【规范要求，现状未实现】** `Tab` 在浮层内循环；浮层首元素获焦 | 是 —— `Esc` 关闭 | `open`（焦点仍陷阱内） |
| `peek`（失焦/贴边半隐） | 球贴边 + 3 秒无操作 | `.ball--peek` → `opacity:.5`；hover 恢复 `opacity:1` | 是 —— 指针移入即恢复 | `idle` |

> **抽屉的硬约束**：
> 1. 抽屉是**窗口内部**元素，`width:280px`、离右边缘 0px ⇒ **禁止任何外扩阴影**（`03-组件规格.md` §3.3）。
> 2. 抽屉开合**不改变对话列宽度、不引起横向滚动**。
> 3. 抽屉里的任何浮层若用 `--shadow-2`，距窗口边缘须 ≥40px（裁剪坑 8）。
> **「失焦收起」目前只作用于球**（`peek`）。窗口形态**不做**失焦自动收起 —— 那会让用户在读文档时窗口突然消失。

## 3. 反馈五级梯度

> **核心原则**：**不要用最重的一级去表达最轻的事。**
> 反过来同样成立：**不要用最轻的一级去表达最重的事** —— 一个会改用户文件的操作，不能只靠按钮变色表示。

### 3.1 五级定义

| 级别 | 名称 | 形态 | 载体 | 典型时长 | 用在哪 |
|---|---|---|---|---|---|
| **L1** | 悬停微亮 | 底色 / 边框一档变化 | 元素自身 | 过渡 `.12s ease`（`03-组件规格.md` §5.1） | 可点元素的 hover |
| **L2** | 边框/焦点变化 | 描边换档 / 焦点环 | 元素自身 | 同上 | focus-visible、按下态、选中态 |
| **L3** | 状态 chip | 12px chip，语义色底 + 语义色字 | 消息头 / 卡片角 | 常驻至状态变化 | 「已中断」「失败」「排队 2」 |
| **L4** | 内联提示 | 卡片 / 段落级文字块，紧贴上下文 | 流内 | 常驻至状态变化 | 空态、加载态、错误态、导出占位 |
| **L5** | 审批卡 / 模态 | 独立卡片 + 倒计时 + 动作按钮 | 流内卡片 / 浮层 | 直到用户决策 | 需要用户决策的高风险操作 |

### 3.2 事件 → 反馈级别 对照表

| 事件 | 级别 | 具体表现 | 判据 |
|---|---|---|---|
| 指针悬停在可点元素上 | **L1** | `.btn:hover` → `--surface-3` 底 + `--border-strong` 边 + `--text` 字 | 只改这三项，不改尺寸 |
| 键盘焦点落在控件上 | **L2** | `outline:2px solid var(--accent)`，`outline-offset:1px` | 焦点环必须可见且不被裁 |
| 按下按钮（active） | **L2** | 加深 inset（不 scale） | `audit.mjs` §2 禁 `scale()` |
| 工具切换项被选中 | **L2** | `aria-pressed="true"` → `--accent-soft` 底 + `--accent` 边 + `--accent-ink` 字 | 状态由 ARIA 属性承载，不用额外图标 |
| 命令面板选中项 | **L2** | **【规范要求】** `aria-selected="true"` → `--accent-soft` 底 + `inset 2px 0 0 var(--accent)` 左指示条<br>⚠ 现状：`src/renderer/index.html:1201` 为 `background:var(--surface-3); color:var(--text);`，**无 accent-soft 底、无左指示条**（见 §9.1） | 左 2px 指示条 = 唯一强调色 |
| 回合被中断 | **L3** | 消息头 `chip--warn`「已中断」 | chip 用 `--warn` 系；不加整块底色 |
| 回合失败 | **L3** | 消息头 `chip--danger`「失败」 | 同上 |
| 队列中有待发消息 | **L3** | `queueChip`（`aria-live="polite"`）显示「排队 n」 | 计数用等宽数字 |
| 连接断开 | **L3** | 状态区 chip + 输入区提示行改文案 | 不只靠文案，必须有可见载体 |
| 文档降级（docx→md） | **L3** | 产出卡降级 chip（`--warn`） | 降级必须显式，不静默 |
| 导出生成中 | **L4** | 该轮次内「正在整理文档」占位块 | 占位在流内原位，不弹 toast |
| 连接失败 | **L4** | 流内错误卡：结论句「连接失败，请重试」+ 原因 + 「详情」折叠 | 错误技术细节折进 `<details>` |
| 导出失败 | **L4** | toast `toast--err`「文档生成失败：<原因>」 | toast 3.6s 自动消失，同时按钮复位可重试 |
| 导出 popover 缺内容 | **L4** | toast `toast--warn`「还没有可导出的回答」 | 警告级 = 可恢复，用 warn 不用 err |
| **写盘 / 改文件 / 执行命令** | **L5** | 审批卡：倒计时 + 真实 diff/预览 + 四档按钮 | 唯一使用 L5 的场景 |
| 终止整轮 | **L5** | 同上，「终止本轮」为独立按钮 | 与「拒绝」分离 |
| 新建会话清空当前流 | **L4 + 确认** | 内联两步确认条（`role="alertdialog"`） | 不可逆 → 需确认 |

### 3.3 选级规则（可机械检查）

1. **可逆、无副作用、不改变持久状态** → L1/L2。
2. **改变本轮会话内的可见状态** → L3。
3. **改变会话内的一块内容 / 一次失败** → L4。
4. **会改用户文件、终止运行、丢弃数据** → L5，且**必须**附预览或后果说明。
5. **同屏同时出现的事件，L5 优先置顶**（如导出进行中 + 审批待决 → 审批卡在上）。
6. **同一事实只用一个级别表达**（原则 1.3）。

## 4. 空态 / 加载态 / 错误态的统一写法

### 4.1 空态

> **公式**：`一句陈述（现状）+ 一个可选动作（下一步）`
> **结构**：标题（`--text`，12.5px/700）→ 说明（`--muted`，11px/1.55）→ 可选动作
> **禁止**：出现"正在准备…""加载中…"这类**假进度**（那是加载态，不是空态）。

| 场景 | 结构 | 示例文案 |
|---|---|---|
| 会话无内容 | 标题 + 场景说明 | 标题「还没有对话」；说明「当前场景：会话」+「问、答、导出文件，不碰你的本地文件」 |
| 列表为空（会话列表 / 模型列表） | 标题 + 一个主动作 | 「没有会话」+「新建会话」 |
| 搜索无结果 | 标题 + 建议 | 「没有匹配「xxx」的会话」+「换个关键词，或新建会话」 |

> 空态**必须至少给一个可点出口**。若该场景确实没有动作可做（纯展示），则说明文案里必须写清"什么条件下才会有内容"。

### 4.2 加载态

> **公式**：`正在做什么（进行中视觉）`
> **结构**：进行中指示 + 一句状态说明。**不放**假数据、不放百分比（除非真能算出来）。
> **规则**：
> 1. 已有内容的区域 → **不换骨架**，只在原位加进行中指示。
> 2. 尚无内容的列表 → 骨架行（3 行）+ 一句说明。
> 3. 连接建立中（`store.conn === 'connecting'` 且无轮次）→ 连接态占位；超过慢阈值后追加"仍在尝试"。

| 场景 | 示例文案 |
|---|---|
| 连接中 | 「正在连接…」 |
| 连接慢（超过慢阈值） | 「仍在尝试连接…」 |
| 文档整理中 | 「正在整理文档」 |
| 模型生成中 | 「思考中」（配合球 `thinking` 态） |
| 审批等待中 | 头部 chip「⚠ 1 项待确认」+ 卡片倒计时 |

> **加载超过 3 秒**必须追加一句"仍在尝试"或给出取消入口，避免"卡住了"的误判。

### 4.3 错误态

> **公式**：`结论句（发生了什么）+ 原因（一句话，可选）+ 下一步（能做什么）`
> **结构**：结论（`--danger-ink`，600 字重）→ 原因（`--muted`）→ 动作按钮 → 技术细节折叠

| 层次 | 写什么 | 示例 |
|---|---|---|
| 结论句 | 发生了什么 + 能不能继续 | 「连接失败，请重试」 |
| 原因 | 一句话，来自错误码映射 | 「原因：模型服务拒绝了请求」 |
| 下一步 | **可点的动作** | 「重试」按钮 |
| 详情 | 原始技术细节，`<details>` 默认收起 | 错误码 / detail 原文 |

> **错误码不直接当文案**。`ERROR_CODES`（`src/shared/protocol.js`）是契约，用户看到的是它的中文映射；映射缺失时用兜底「暂时无法完成这个操作」。

### 4.4 错误文案的绝对禁止项

| 禁止出现 | 为什么 | 正确替代 |
|---|---|---|
| 任何密钥 / token / API key / 密码 | 一旦显示即视为泄漏 | 完全不显示；审计侧按审批设计 §7.2 第 ③ 步替换为 `<redacted>` |
| 绝对家目录与内部绝对路径 | 泄漏用户目录结构 | 家目录 → `~`；绝对路径 → `<path:文件名>`（审批设计 §7.2） |
| IPC 通道名（如 `minipi:approvalDecide`） | 内部实现泄漏，且用户无法据此行动 | 「提交审批失败，请再试一次」 |
| 堆栈 / `Error:` / 文件行号 | 无行动价值，且长 | 折进「详情」折叠 |
| 裸露的错误码（如 `APPROVAL_NOT_FOUND`） | 用户看不懂 | 「这张审批已不存在（可能已超时或已处理）」 |
| 「未知错误」「出错了」 | 没有下一步 | 结论句 + 「重试」 |

> **唯一例外**：`bash` / `powershell` 的**命令正文**在审批卡上**原样显示、不得脱敏**（审批设计 §7.3）—— 命令是用户判断的唯一依据。但它**不进入任何 toast、错误卡或持久化文件**。

## 5. 审批交互规范

> 契约层（字段、三值 action、超时、持久化、审计脱敏）以 `docs/minipi-approval-gate-design.md` 为唯一来源。本节只管**前端怎么呈现、怎么响应键盘、怎么把拒绝理由回灌**。

### 5.1 四档动作的呈现顺序与措辞

> **顺序 = `card.actions` 数组顺序**（服务端是定义方）。渲染层**不得**自行排序、不得自行增删动作。
> 当前落地四值：`allowOnce` / `allowSession` / `denyWithInstruction` / `terminate`。

| 序 | `action` | 按钮文案（固定） | 视觉权重 | 按钮 class | 含义一句话（tooltip） |
|---|---|---|---|---|---|
| 1 | `allowOnce` | **允许一次** | 主动作 | `btn btn--sm btn--primary` | 放行这一次（不改参）；下次同工具还会再问 |
| 2 | `allowSession` | **本会话允许此文件** | 次动作 | `btn btn--sm` | 本会话内对**这个文件**不再弹卡（换文件会重新问；仅内存，退出即失；沙箱仍生效） |
| 3 | `denyWithInstruction` | **拒绝并说明** | 警示 | `btn btn--sm btn--warn` | 拒绝这一次，并把上面那句说明转给模型 |
| 4 | `terminate` | **终止本轮** | 危险 | `btn btn--sm btn--danger` | 拒绝并停止这一整轮运行 |

> **措辞红线**：
> 1. 按钮文案是**产品语言**，字段值是**契约语言**（`allowOnce` 等）。二者不得互换、不得把字段值显示给用户。
> 2. 「拒绝」与「终止本轮」**不得**用同一个词。「取消」**禁止**用作审批按钮文案 —— 它在产品里指"关掉浮层"，与"拒绝一次操作"是两回事。
> 3. 旧值 `deny` 仍被 IPC 层接受（映射到 `denyWithInstruction`，无 instruction 时语义等同），但**前端只渲染 `card.actions`**，不自行做别名映射。

### 5.2 默认焦点与键盘可达性

| 项 | 规定 |
|---|---|
| **默认焦点** | **【规范要求，现状未实现】** 卡片出现时，焦点落在**「拒绝并说明」的说明输入框**（若该档可用）或卡片的**第一个按钮「允许一次」**；**绝不给任何"放行"类按钮默认焦点** —— 误触 Enter 即放行是不可接受的风险。<br>⚠ 现状：`buildApprovalCard()` 无任何 focus 调用；全文件唯一 focus 逻辑（`src/renderer/index.html:6233`）把焦点给第一个 `[data-approval-action]`（即 `allowOnce`，**恰好是放行按钮**）—— 与本条规范**完全相反**，属高优先级待修项（见 §9.1） |
| **Tab 顺序** | 卡片内自上而下：说明输入框 → 允许一次 → 本会话允许此文件 → 拒绝并说明 → 终止本轮；卡片**之外**的元素在卡片存在期间**不可 Tab 到** |
| **Esc** | `Esc` **不**等于"拒绝"。`Esc` 只关闭**浮层**（popover / 菜单 / 面板）；审批卡不是浮层，`Esc` 对它**无效** —— 审批必须由显式点击或超时决定（fail-closed） |
| **Enter / Space** | 焦点在按钮上时激活该按钮；焦点在说明输入框时 `Enter` 换行、`Ctrl+Enter` 提交「拒绝并说明」 |
| **超时** | 到点后全部按钮 `disabled`，卡片追加「已超时，已拒绝」，焦点移到卡片容器（`tabindex="-1"`）并朗读状态 |
| **提交中** | 一旦点击：全部按钮 `disabled` + `.approval--deciding`，**不乐观移除卡片**（以服务端 `phase:"cancel"` 为准） |

> **为什么不给「允许一次」默认焦点**：审批是一个"回车即放行"的陷阱。默认焦点落在**拒绝路径**上，让"回车"默认落在安全侧。
> **焦点归还**：审批卡因服务端 `cancel` 消失时，焦点归还到**触发该卡的位置**（输入区），不得丢焦（丢焦 ⇒ 后续 Tab 从文档开头开始，用户失去位置感）。

### 5.3 「本会话允许此文件」的作用范围必须写清

> 这一档是四档里**最容易被误解**的一档（用户会以为"以后这个文件都不用管了"）。落地语义（`src/main/pi/approval.js`）：按**单个文件绝对路径全等匹配**、**单槽记忆**、**仅内存**。

| 必须让用户看到的限定 | 展示位置 | 措辞 |
|---|---|---|
| 只对**这一个文件** | 按钮 tooltip + 卡内说明行 | 「仅对这个文件生效」 |
| 绝对路径**全等**匹配 | 卡内说明行 | 「按完整路径匹配，同名不同路径不算」 |
| **换文件即失效** | 卡内说明行 | 「换到别的文件会重新询问」 |
| **仅本次运行有效** | 卡内说明行 | 「只存在内存里，退出 minipi 即失效」 |
| **沙箱仍然生效** | 卡内说明行 | 「仍然只改你打开的这个文件」 |

> **推荐措辞（卡内说明行，单行）**：`仅本会话 · 仅此文件（完整路径匹配）· 换文件会再问 · 退出即失效`
> **禁用措辞**：「永久允许」「以后都不用问」「记住这个选择」「信任此目录」—— 全部与实际语义不符。
> **单槽记忆的含义**：同一会话里若又对**另一个**文件点了本档，**替换**前一个记忆（`this._allowFile.set(sessionId, key)` 覆盖写）。前端**不得**让用户以为可以同时记住多个文件。若用户连点两个不同文件，第二次点下去时应在卡上追加一行「上一个记忆（xxx）将被替换」。
> **混合工具批不给这一档**：`alwaysAllowEligible` 为 `false`（批内工具不唯一）时该按钮 `disabled`，并说明「这一批包含多种操作，只能逐次确认」。

### 5.4 拒绝并说明 → 回灌给模型

| 项 | 规定 |
|---|---|
| 输入 | 卡内 `textarea`，`maxlength = 500`，占位「选填：拒绝后希望它怎么做（会转给模型，≤500 字）」 |
| 可选性 | **选填**。空串**不发** `instruction` 字段，服务端回落到默认拒绝文案 |
| 提交 | 与「拒绝并说明」按钮同一个动作完成，不额外加提交按钮 |
| 回灌时机 | 决定**之后**立即回灌；模型**不重试**该操作，改为按说明换路径 |
| 回灌内容 | 用户的**原话**（trim 后）。前端**不改写、不总结、不加前缀** |
| 三种拒绝的回灌文案必须区分 | 超时 / 用户拒绝 / 终止本轮（审批设计 §5.3）—— 模型的应对完全不同 |
| 前端反馈 | toast：「已拒绝，并转达了你的说明」/「已拒绝」 |

> **≤500 字**是**双侧**限制：前端 `maxlength` 拦一道，服务端也应截断。超长时前端给字数提示，不静默截断。
> **回灌的信任边界**：回灌内容来自用户输入框，**不得**被当作指令执行；渲染层只做"原样传给模型"，不解析、不执行其中的任何命令。

### 5.5 审批卡的三类内容模板

| `kind` | 标题 | 必须展示 | 不得展示 |
|---|---|---|---|
| `write` | 写入文件 | 目标路径（`~` 化）、字节数、内容预览（前 2000 字符）、**是否覆盖已有文件**（覆盖则重警示） | 全文 |
| `edit` | 修改文件 | 目标路径、**真实 diff**（`- 旧行 / + 新行`）、`+N -M` 统计 | 只给文件名 / 只给 `newText` / 只给第一条 edit |
| `command` | 执行命令 | **完整命令原文**、执行目录、超时秒数、高危标记（`risk:"high"` ⇒ 红框） | 被脱敏过的命令 |

> 改动过大（超 `APPROVAL_DIFF_MAX_BYTES = 65536`）时 `tooLargeToDiff:true` ⇒ 只给 `+N -M` 并注明「改动较大，仅显示统计」。
> 批量合并卡：按 `kind` 分组展示，条目 >5 时折叠「还有 N 条」，单卡最多 `APPROVAL_BATCH_MAX_ITEMS = 20` 条。
> ⚠ **【规范要求，现状未实现】** 现状 `buildApprovalCard()` 渲染**全部** batch 项，无「还有 N 条」折叠（见 §9.1）。
> 三个按钮作用于**整批**（批量语义，不是逐条矩阵）。

## 6. 无障碍

### 6.1 焦点管理

| 项 | 规定 | 依据 |
|---|---|---|
| 焦点环样式 | `outline:2px solid var(--accent)`；`outline-offset:1px` | `03-组件规格.md` §7 + 裁剪坑 11 |
| 焦点环对比度 | 与相邻底色 ≥3:1 | `docs/minipi-ui-refresh-spec.md` §3.3 |
| 唯一焦点环来源 | `:focus-visible`；禁止 `outline:none` 却不自绘 | `src/renderer/index.html:215` 已有全局规则 |
| 贴边控件 | `outline-offset` 保持 1px；贴边按钮改用 `box-shadow` 内描边 | 裁剪坑 11 |
| 键盘可达顺序 | 与视觉顺序一致（从上到下、从左到右）；**不**用 `tabindex` 正数重排 | HTML 规范 |
| 浮层打开 | 焦点移入浮层首个可聚焦元素；模态浮层内 `Tab` 循环（焦点陷阱） | — |
| 浮层关闭 | 焦点**归还**到触发元素；触发元素已消失时，落到最近的合理容器（`tabindex="-1"`） | — |
| 审批卡消失 | 焦点归还输入区 | §5.2 |
| 球 | 球是可聚焦控件，`aria-label` 必须随 `data-ball` 更新（「当前状态：空闲 / 思考中 / 未读 / 待确认」） | `src/renderer/index.html:1379` 已有 |

> **焦点陷阱只给模态浮层**（设置面板、确认条）。非模态浮层（popover、菜单、命令面板）**不设陷阱**，但 `Esc` 可关、焦点仍在文档流内可达。

### 6.2 对比度要求

| 层级 | 要求 | 实测值（暗 / 浅） |
|---|---|---|
| 正文（`--text`） | ≥4.5:1 | 15.17 / 17.40（对 `--surface`） |
| 次级正文（`--text-2`） | ≥4.5:1 | 8.21 / 8.72 |
| 三级文字（`--muted`） | ≥3:1 | 5.04 / 5.33 |
| 占位/禁用（`--muted-2`） | **不承载任何信息** | 2.55 / 2.78 ⚠ 禁用级 |
| 语义文字（`--accent-ink` / `--danger-ink` / `--success-ink` / `--warn-ink` / `--violet-ink`） | ≥4.5:1 | 9.33/6.65 · 8.16/7.96 · 10.10/6.63 · 13.27/7.27 · 8.81/8.73（暗/浅，对 `--surface`；真值以 `node ui-optimization/future-ui/audit.mjs` 实跑为准） |

> **三级文字的硬规定**：需要弱化正文时用 `--muted`，**不得**新增第四级文字令牌、**不得**用 `--muted-2` 承载信息（`02-令牌规格.md` §1.2 已明确不引入三级文字令牌）。
> **状态色只作载体**：状态色出现在 2px 边 / chip 底 / 状态文字上；状态**本身**不得是唯一信息载体 —— 每个状态 chip 必须**同时有文字**（颜色盲可读）。

### 6.3 `aria-live` 与流式输出

| 区域 | 属性 | 用途 | 规则 |
|---|---|---|---|
| 流式正文 | `aria-live="polite"`（**建议加**，现状未见） | 让读屏用户听到模型输出 | **不得**对每个 delta 都触发朗读 —— 必须**节流**：建议以"段落完成"或固定间隔为单位更新 live region |
| 队列 chip | `aria-live="polite"`（已有 `queueChip` / `queueChipFull`） | 排队数量变化 | 数字用 `aria-label` 给完整读法 |
| 设置面板状态 | `aria-live="polite"`（已有 `settingsStatus`） | 设置保存结果 | — |
| 错误 toast | `role="alert"`（现状 `kind==='err'`） | 错误必须打断 | 普通 toast 用 `role="status"` |
| 审批卡 | **【规范要求，现状为 `role="group"`】** `role="region"` + `aria-label` | 进入/离开时告知 | 卡片出现时应被朗读（倒计时是时效信息） |

> **流式朗读的取舍**：`aria-live` 逐字朗读会与用户正在读的内容打架。本规范取"**节流到段落级**"：正文流式追加时**不**实时播报，只在**回合落定**时把最终正文作为一个整体播报。实现层面即：live region 挂在**落定后的容器**上，不挂在流式容器上。
> **不得**用 `aria-live="assertive"`（会打断用户当前朗读）。

### 6.4 `prefers-reduced-motion` 降级

| 动效 | 降级后 | 状态可读性 |
|---|---|---|
| 球 `thinking` 旋转环 | `animation:none` → **停在静态 1/4 弧**（`border-top-color: var(--accent)`，右侧 30% 渐隐） | 保留 —— 仍看得出"在转" |
| 球 `await` 徽标脉冲 | `animation:none` → 停在静态金色 | 保留 |
| 抽屉 / 面板开合 | `transition:none` | 保留（瞬时切换） |
| 通用过渡 | 全局 `transition-duration:.001ms` | — |

> **降级铁律**：关掉动效**不得**关掉状态。任何一个"靠动效表达状态"的设计，在 `reduce` 下必须有一个静态等价物。
> **禁止**用 `prefers-reduced-motion` 的间隙引入新动效（例如"关掉旋转后改成呼吸缩放"）。

### 6.5 其他

| 项 | 规定 |
|---|---|
| 图标按钮 | 全部必须有 `aria-label`（现状 `.iconbtn` 已有） |
| 装饰性图形 | `aria-hidden="true"`（如 `mini__brand` 的 sprite `<svg>`） |
| 聊天流内 SVG | **零** `<svg>` 元素（`qa-renderer-edge` C5 判 XSS）；动态图标走 `iconEl()` → `<span class="ico-mask">` + `mask-image` |
| 隐藏文本 | `.sr-only`（已有），用于给图形按钮补文字 |
| 状态不只靠颜色 | 每个状态 chip 带文字；diff 的增删同时用 `+` / `-` 前缀与颜色 |
| 语言 | `lang="zh-CN"`；`<body>` 的 `data-mode` / `data-scene` 不作为语义来源 |

## 7. 文案规范

### 7.1 术语表（唯一命名，一个东西只有一个名字）

> **规则**：下表左列的名字是**唯一合法**的名字。右列的词**禁止**出现在任何用户可见文案里。
> **机制**：新增文案前先查本表；表里没有的词，先在本表登记再使用。

| 概念 | **唯一名称** | 禁止使用 | 说明 |
|---|---|---|---|
| 模型生成并落盘的文件 | **产出** | 结果、产物、成品、输出物、生成物 | 「产出卡」「产出（未落盘）」 |
| 用户的一句提问 | **提问** | 消息、指令、prompt、问询 | 「第 N 轮」是分轮计数，不是消息 |
| 一轮完整的问答 | **轮次** | 回合、会话轮、turn | 「第 1 轮」 |
| 一次会话 | **会话** | 对话、聊天、thread | 「会话列表」 |
| chat 场景（用户可见） | **会话** | chat、聊天、快速问答 | 契约 id `chat` 不外露 |
| work 场景（用户可见） | **文档** | work、文档模式、本地模式 | 契约 id `work` 不外露 |
| 模型正在工作 | **思考中** | 生成中、处理中、运行中 | 球态与提示行统一 |
| 用户主动叫停 | **已中断** | 已取消、已停止、已撤销 | 消息流 chip 文案 |
| 模型这一轮失败 | **失败** | 出错、异常、崩了 | 消息流 chip 文案 |
| 写文件前的用户决策 | **审批** | 授权、确认、许可 | 审批卡 / 待确认 |
| 审批四档之一 | **允许一次 / 本会话允许此文件 / 拒绝并说明 / 终止本轮** | 允许、始终允许、拒绝、中断整轮 | 见 §5.1，措辞固定 |
| 让模型换做法 | **说明** | 指令、意见、备注、反馈 | 「拒绝并说明」里的那句话 |
| 窗口形态 | **悬浮球 / 小窗 / 大窗** | 球态、mini、full、模式 | 契约 id `ball`/`mini`/`full` 不外露 |
| 关闭窗口形态 | **收起** | 最小化、折叠、退出 | 「收起回球」「收起为小窗」 |
| 右侧信息栏 | **抽屉** | 侧栏、右栏、详情面板 | 现状已改抽屉（默认收起） |
| 未读提示 | **有产出** | 未读消息、红点提醒 | 球态 `unread` 的用户可见说法 |
| 等待用户决策 | **待确认** | 等待中、挂起、阻塞 | 球态 `await` 的用户可见说法 |

### 7.2 文案结构公式

| 类型 | 公式 | 例 |
|---|---|---|
| 按钮 | 动词 + 宾语，≤6 字 | 「允许一次」「拒绝并说明」「另存为」 |
| 状态 chip | 名词性短语，2–4 字 | 「已中断」「失败」「排队 2」 |
| 空态标题 | 「还没有…」 | 「还没有对话」 |
| 加载态 | 「正在 + 动宾」 | 「正在整理文档」 |
| 错误结论 | 「<失败对象> + 失败，请<下一步>」 | 「连接失败，请重试」 |
| 提示行 | 用 `·` 分隔的短语串 | 「Enter 发送 · ⇧Enter 换行 · Esc 中断」 |
| Tooltip | 一句话讲清后果，含作用域与有效期 | 「本会话内对**这个文件**不再弹卡（换文件会重新问；仅内存，退出即失；沙箱仍生效）」 |

### 7.3 明确避免的措辞

| 避免 | 原因 | 改成 |
|---|---|---|
| 「永久」「一直」「以后都」 | 与「仅内存、退出即失」不符 | 「本会话内」「退出即失效」 |
| 「安全」「放心」「已受保护」 | 空洞承诺，且审批的价值恰在"你自己判断" | 说清具体边界（哪个文件、什么范围） |
| 「操作失败」 | 没有对象，用户不知道哪一步失败 | 「文档生成失败」 |
| 「点击这里」/「点这里」 | 界面里没有"这里" | 直接写动作名：「重试」「重试连接」 |
| 「稍等」/「请耐心等待」 | 无信息量 | 「正在整理文档」（说清在做什么） |
| 「暂不支持」「功能开发中」 | 假入口的遮羞布 | 不画这个入口 |
| 「你确定吗？」 | 没有信息 | 写清后果：「将覆盖已存在的 周报.md」 |
| 中英混杂（`已 timeout`） | 不一致 | 「已超时」 |
| 感叹号收尾 / 「哦」「呢」 | 与仪器面板的语气不符 | 平陈述句 |
