## 1. 产品视觉定位

### 1.1 产品是什么，在用户工作流里处于什么位置

minipi 是 **Electron 桌面常驻悬浮 AI 助手**。它不是「打开一个网页去聊天」，而是**一直待在桌面上、被叫到时才展开**的辅助工具。

这决定了视觉上的三件事：

| 事实 | 视觉后果 |
|---|---|
| **常驻桌面**，用户一天要看见它几十次 | 它必须**低噪音**。任何持续闪烁、发光、呼吸动画都会变成疲劳源。科技感必须是**静态的**，不是动态的。 |
| **三种几何连续形变**：球 `48×48` → 小窗 `360×480` → 大窗 `960×680` | 同一套视觉语言要在三个尺寸上都成立 —— 48px 上是「密」（明度分层挤进 48px），360 上是「疏」，960 上是「分层」。**同一手法、三种密度**是本方案的硬指标。 |
| **桌面是透明的，窗口是矩形** | 一切外扩阴影/blur 都会溢出窗口矩形，在深色壁纸上显示为一圈**淡方形边**（用户已两次投诉）。**体积感只能靠 inset 表达。** |

### 1.2 视觉人格三词（每词附可判定标准）

> 判据必须能被**一眼**或**一次 grep** 判定，否则就是形容词，不是规范。

| 词 | 含义 | 可判定标准（通过 / 不通过） |
|---|---|---|
| **精密** | 每个数字、每条线、每个间距都有确定的量级，不靠"差不多" | ✅ 数字全部 `font-variant-numeric: tabular-nums`（读数、时间戳、字节数、token 数、版本号、行号、上下文占比）；网格单元全局统一 **24px**；分区标题短标尺 **18–26px × 1px**，**不超过 30px**（超过就读成下划线而非刻度标尺）<br>❌ 同一类元素在不同位置宽度/字号不一致；数字跳动导致列宽抖 |
| **克制** | 颜色、阴影、动效都被明确限量 | ✅ 实色主色元素边长 **≤64px**；`var(--accent)` 引用 **≤60 处**（现状 52）；彩色面积 **<5%**（本方案目标 <2%）；网格线透明度 **≤0.05**；`--fx-glow-accent` **≤0.14**；**0 个** `transform: scale()`<br>❌ 整块状态色背景、大面积霓虹、外发光、hover 缩放 |
| **可信** | 界面读起来像一台仪器，而不是一个玩具 | ✅ 状态色只落在 **2px 边 / chip 底 / 状态文字** 三类载体上；每个状态有**唯一**表达载体；`--muted-2`（实测 2.55:1 / 2.78:1）**不承载任何信息**<br>❌ 同一个状态同时用 chip + 边框 + 文案三处重复标注；弱化文字仍用不可读色 |

### 1.3 与通用 AI 聊天窗口的明确区隔

通用 AI 聊天窗口（ChatGPT / Claude 网页版 / 各类套壳）的视觉语法是：**气泡 + 圆角 + 大留白 + 蓝紫渐变 + 拟物 emoji 助手**。minipi 刻意与之分道：

| 维度 | 通用 AI 聊天窗口 | **minipi** | 差异落点 |
|---|---|---|---|
| 助手消息 | **气泡**（圆角矩形、有底色、有阴影） | **去气泡**，用 5px **轴点 + 1px 渐隐轴线** | `03-组件规格.md` §4.1 |
| 用户消息 | 气泡（与助手对称） | **唯一保留气泡的一方**（`--surface-2` + 右侧一小段主色边表方向） | §4.2 |
| 层级手段 | 阴影 + 圆角 + 底色块 | **四级明度阶梯**：`--bg` → `--surface` → `--surface-2` → `--surface-3` | `02-令牌规格.md` §1.1 |
| 边框 | 1–2px 实色描边 | **1px 发丝线**三级：`--border` / `--border-strong` / `--fx-edge-hair` | §7 像素手法表 |
| 数字 | 比例字体，列会抖 | **等宽 tabular-nums** | §4 字体与数字 |
| 状态表达 | 大色块 / 彩色胶囊 | **2px 语义边**（绿=落盘、黄=降级、红=失败） | §4.5 产出卡 |
| 装饰 | 渐变、发光、模糊、噪点 | **网格纹理 ≤2% 不透明度，只铺空白容器** | §2 原则五 |
| 品牌符号 | emoji / 拟物头像 | **π：浅色实体，浮雕于球面**（π 必须全程比气泡亮） | `ball-3d` §4.1 |

> **一句话区隔**：别的窗口在**聊天**，minipi 在**报告读数**。

### 1.4 三个几何的视觉分工

| 几何 | 视觉角色 | 允许的密度 | 不允许 |
|---|---|---|---|
| 球 `48×48` | **品牌锚点**：这套语言的最密版本 | 球面三段径向明度 + 顶部 1px 内高光 + 底部 AO + 底部冷反射 + ≤2px 镜面高光 | 网格纹理（48px 里放 24px 网格 = 2×2 方块，直接毁掉球形）、发光边框、hover 放大 |
| 小窗 `360×480` | **工作面**：一屏一件事 | 面板明度分层全量 + 顶边内高光全量；网格**降级**为只铺空白处；等宽数字只用于时间戳 | 网格压正文行、发光边框、玻璃拟态 |
| 大窗 `960×680` | **控制台**：三栏（会话列 208px / 对话区 / 抽屉 264px） | 明度分层全量 + 内高光全量；网格有限铺设；**窗口内部浮层允许外阴影** | 表格/代码块内部铺网格；抽屉内元素用外扩阴影（离右边缘 0px） |

## 2. 六条视觉原则

> 每条格式固定为「**原则 → 为什么 → 落地判据 → 常见违反示例**」。
> **判据尽量可机械检查**：能写成 `grep` / `audit.mjs` 断言的就写成断言；不能机械化的标注「人工评审项」。

### 2.1 原则一：明度分层优先于色彩

- **原则**：**先解决"这块比那块高还是低"，再考虑"这块是什么颜色"。** 层级靠 `--bg` / `--surface` / `--surface-2` / `--surface-3` / `--composer` 的明度差表达；颜色只负责语义，不负责层级。
- **为什么**：明度是**唯一在 48px、360px、960px 三种几何下都成立**的层级手段。色相对比在小尺寸上会退化成"颜色块"，在浅色主题下还会被底色吃掉；而明度差在暗色主题是「变亮表示浮起」，在浅色主题是「变白表示浮起」，**同一套结构换锚点即可**，天然满足双主题同构。冷调仪器面板的气质也正来自此 —— 仪器的层次感从来不是涂上去的，是光打出来的。
- **落地判据**：
  1. 每一处"看起来浮起/看起来是子块"的表达，**必须**能在令牌表里指出对应的 `--surface-*` 层级或对应的一次 `inset`，找不到 = 违规。
  2. 组件内**禁止**出现任何 hex / rgb() / rgba() 字面量；需要透明度一律 `color-mix(in srgb, var(--x) N%, transparent)`，**不新建 alpha 令牌**。
  3. 暗色主题的层级是**变亮**（`--bg #181818` → `--surface #202020` → `--surface-2 #242424`），浅色主题是**变白**（`#f7f7f7` → `#ffffff` → `#fafafa`）。**禁止**在任一主题里写死"某个色一定更浅"。
  4. `--surface-3` **禁止承载正文**（对比度不足）；`--composer` **禁止**与 `--surface` 同级使用（会让输入框"浮出"卡片）。
- **常见违反示例**：
  - ❌ 给一个子区块单独配一个更饱和的蓝底，认为"这样它就区分出来了" —— 这是用色相冒充层级。
  - ❌ 暗色主题下把次级面板做成 `#333`（比 `--surface` 亮但没在阶梯上），浅色主题再单独调一遍 —— 两套结构，违反双主题同构。
  - ❌ 用 `--accent-soft` 当面板底 —— 它是选中行/chip 的底，不是层级工具。

### 2.2 原则二：发丝线优先于粗边框

- **原则**：边界用 **1px 发丝线**，三级递进：`--border`（卡片描边）< `--border-strong`（输入框/浮层描边）< `--fx-edge-hair`（分区标题下的渐隐亮线）。**禁止加粗到 ≥2px**，禁止当强调边框。
- **为什么**：透明窗是**矩形**，圆角之外是桌面。粗边框和重描边在小尺寸（48px 球、26px 图标按钮）上会直接吃掉有效像素，也会把"精密仪器"读成"表单控件"。1px 恰好是 48px 的 2.08%，是最小可见单位 —— 足够表达边界，又不喧宾夺主。
- **落地判据**：
  1. 全局只有三种边框亮度层级；`--divider`（分区之间的分隔线）与 `--border` **不混用**。
  2. 分区标题下的亮线用 `linear-gradient(90deg, transparent, var(--fx-edge-hair) 22%, var(--fx-edge-hair) 78%, transparent)` 的**伪元素**，**禁止**给正文分隔用（会读成双线）。
  3. 头部若同时要 `border-bottom` 和渐隐亮线，伪元素必须放 `bottom:-1px` 覆盖 border 位置，**不得**叠加成 2px。
  4. 短标尺（分区标题下的 accent 线）**18–26px × 1px**，不透明度 55–60%，**不超过 30px**。
  5. 图标按钮 focus 环 `outline:2px solid var(--accent)` + `outline-offset:1px`；**禁止** `outline-offset:2px`（贴边按钮会被裁成半个环）。
- **常见违反示例**：
  - ❌ 用 `border: 2px solid var(--accent)` 做"选中态" —— 2px 彩色实边在小窗 360 宽里会让 1px 文本对齐整体偏移。
  - ❌ 头部同时保留 `border-bottom:1px` 和 `::after` 亮线 → 界线变成 2px。
  - ❌ 用 `border-left` 画消息轴线 → 轴线参与盒模型，把正文挤动 1px。必须用 `::after` 绝对定位。

### 2.3 原则三：inset 光影优先于外发光

- **原则**：体积感**只**由 `box-shadow: inset ...` 表达。窗口根卡片、`.ball`、以及任何**靠近窗口边缘**的元素，**禁止**任何 `drop-shadow` / `text-shadow` / 外扩阴影 / 外发光。
- **为什么**：Electron 透明窗的裁切边界 = 窗口矩形。外扩阴影/blur 的**溢出部分落在矩形外的透明区**，在深色壁纸上会显示为一圈**淡方形边** —— 这正是用户**已经投诉两次**的现象。而 `inset` 永远落在元素自己的矩形内，**不可能越界**。换句话说：`inset` 不是"为了酷"，是这里**唯一安全的选项**。
- **落地判据**：
  1. `--shadow-1` / `--shadow-2` **只允许**用在窗口**内部浮层**（toast / popmenu / 设置面板 / 命令面板），且该浮层**距窗口边缘 ≥40px**（四周有 ≥40px 不透明内容像素承接阴影，不会触及窗口矩形边界）。
  2. `--fx-glow-*` 只允许用在**距窗口边缘 ≥16px** 的元素上。
  3. `--fx-shade-inset` 仅限球与 **≤64px** 的小构件。
  4. 球壳的三层光影全部 inset：顶部 1px 内高光 + 底部 AO 内暗 + 底部冷色环境反射；需要"球比桌面高"的感觉 → 靠**球缘暗角**（径向渐变端）+ 底部 AO，**不得**改成外阴影。
  5. 顶边内高光统一 `inset 0 1px 0 var(--fx-lit-top)`；`--fx-lit-top` 暗色值 **禁止 >0.12**（浅色主题会过曝）。
- **常见违反示例**：
  - ❌ `.ball{ box-shadow: 0 4px 12px rgba(0,0,0,.4) }` → 球外一圈淡方形边。
  - ❌ 给抽屉里的小卡片加 `0 2px 6px` —— 抽屉 `width:264px`、离右边缘 0px，阴影溢出即裁。
  - ❌ 用 `filter: blur()` 给标题做发光 —— 小字号发糊 = 有效对比下降。

### 2.4 原则四：单点强调，彩色面积是受控预算

- **原则**：主色 `--accent` 是**稀缺的注意力预算**，不是主题色。实色主色只允许出现在 **≤64px** 的小构件；彩色面积 **<5%**（本方案目标 **<2%**）。
- **为什么**：冷调仪器面板的科技感来自**秩序与读数**。一旦彩色面积放开，明度阶梯立刻失效 —— 界面变成"一堆彩色块"，用户也失去了"这里才是重点"的判断依据。而且 `accent` 的实色块是**跨主题重色**，它的面积是唯一能让两个主题同时失控的旋钮。
- **落地判据**：
  1. `--accent` 的合法落点**仅限四类**：当前选中项的左侧 2px 指示条（`inset 2px 0 0 var(--accent)`）、主按钮（`--accent-2` 底）、焦点环、消息轴点。
  2. 状态色（`--danger` / `--success` / `--warn` / `--violet`）**只允许**出现在 **2px 边 / chip 底 / 状态文字** 三类载体上；**禁止**整块状态色背景。
  3. `--violet`（次级强调，用于 diff hunk / md 格式 chip）**禁止**与 `--accent` 同时出现在同一视区做主强调。
  4. `--accent` **禁止**用作大段文字色；`--accent-ink` 才是主色系文字（链接、代码标识），实测对比度 **9.33:1（暗）/ 6.65:1（浅）**。
  5. 状态色作文字时**必须**用 `-ink` 变体（`--danger-ink` / `--success-ink` / `--warn-ink` / `--violet-ink`），不用裸色。
- **常见违反示例**：
  - ❌ 整张审批卡铺淡红底表示"已拒绝" → 彩色面积爆表，且红色底会让人误以为这是可点区域。
  - ❌ 主按钮用 `--accent`（而非 `--accent-2`）且带主色描边 → 实色面积翻倍。
  - ❌ 同一个视区里左轴点是蓝、右侧产出卡左边是紫、顶部 chip 又是蓝 → 主强调失焦。

### 2.5 原则五：网格是底，不是覆盖

- **原则**：网格纹理（24px 单元、线色 2.0%）**只铺空白容器**（空态卡片、命令面板背后、消息区容器底）。**绝不叠在正文行、代码块、diff、表格正下方。**
- **为什么**：网格是**唯一**提供"这是个技术面板"氛围的低成本纹理，代价极小；但它的破坏力同样极小地被低估 —— 12.5px 正文 + 1px 周期线 = 持续的视觉节拍干扰，读久即疲劳。**纹理必须出现在"没有内容的地方"，因为网格想表达的是"这块是空的、待填充的面板"。**
- **落地判据**：
  1. `--fx-grid-line` 透明度暗 **2.0%** / 浅 **2.0%**，**禁止 >0.05**；主轴线 `--fx-grid-line-2` 暗 5% / 浅 6%，**禁止**拿来做分隔线（用 `--divider`）。
  2. `--fx-grid-size` 全局统一 **24px**，**禁止 <16px**（会成噪点）。
  3. `--fx-grid` **禁止**用于代码块 / diff / 表格内部（11px 等宽字 + 网格 = 摩尔纹）。
  4. **小窗的具体做法**：网格铺在消息区容器 `background-image` 上，**正文元素自带底色**（消息行本身透明，靠行间间隙露出网格）—— 视觉上网格只在空白处出现。**禁止**给正文段落加 `background: var(--surface)` 去"压住"网格（那会让聊天流变成一列方块）。
  5. `--fx-grid-accent`（强调轴 / composer 顶边渐变）**禁止 >0.14**。
- **常见违反示例**：
  - ❌ `.msg{ background: var(--surface) }` + 容器铺网格 → 聊天流变成一列色块，网格的意义全失。
  - ❌ 代码块内部铺 24px 网格 → 摩尔纹。
  - ❌ 球里铺 24px 网格 → 48px 里出现 2×2 方块，直接毁掉球形。

### 2.6 原则六：数字必须等宽

- **原则**：所有**会变化的数字**用 `--mono` + `font-variant-numeric: tabular-nums`。凡是"读数"性质的数字，等宽是**语义要求**，不是美化。
- **为什么**：tabular-nums 保证每个数字占**等宽**。比例字体下，数字宽度随内容变化 —— 时间戳从 `1:10` 跳到 `12:00`、token 数从 `999` 跳到 `1000`，整列会左右抖。这在"仪器"隐喻下是致命的：读数抖动的仪表看起来不可靠。顺带的好处是数字对齐后**天然可扫读**，这正是"读数"应有的样子。
- **落地判据**：
  1. 等宽数字的**适用范围**：时间戳、字节数、token 数、版本号、行号、上下文占比、状态行读数、diff 行号。
  2. diff 行号列（**当前尚未实现**；若实现则必须 `tabular-nums` + 右对齐 + 固定 `min-width`（否则增删行会让行号列抖动）。
  3. **正文不混排**：等宽数字只出现在专用位置（meta 行、读数位），**不塞进 12.5px 正文段落**。
  4. 字体栈固定：`--mono` = `ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace`；`--sans` = `system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif`。**禁止引入外部字体**（无 `@font-face`、无 CDN）。
  5. diff / 代码块 / 版本号等**已经是等宽**的场景**禁止**再叠 `font-weight` 变化。
- **常见违反示例**：
  - ❌ 时间戳用 `--sans` → 每分钟抖一次，肉眼可见地"不安"。
  - ❌ 版本号用 `--sans` 且右对齐 → 与相邻行不对齐。
  - ❌ 为了"数字更好看"给读数加 `font-variant-numeric: proportional-nums` → 等于把这条原则删掉。

## 3. 色彩策略

### 3.1 色彩的三个角色分工

| 角色 | 令牌 | 职责 | 严禁越界 |
|---|---|---|---|
| **结构色** | `--bg` / `--bg-2` / `--surface` / `--surface-2` / `--surface-3` / `--composer` | 明度阶梯，表达层级 | 禁止承担语义；禁止承载正文（`--surface-3`） |
| **语义色** | `--accent` / `--danger` / `--success` / `--warn` / `--violet`（各带 `-ink` / `-soft`） | 表达**状态与指向** | 禁止做层级、禁止整块背景、禁止大段文字 |
| **光色** | `--fx-lit-top` / `--fx-shade-bottom` / `--fx-shade-inset` / `--fx-edge-hair` / `--fx-glow-accent` / `--ball-*` | 表达**光**（不是颜色） | 全部必须以 `inset` 落地；禁止外扩 |

> 光色是本方案与"配色方案"最本质的区别：**光不是一种颜色，光是叠在明度阶梯上的一层半透明**。因此光色令牌永远是 `rgba(255,255,255,.xx)` 或 `rgba(0,0,0,.xx)` 这种**单色 + 透明度**，永远不用来直接铺底。

### 3.2 状态色的角色与用量上限

| 语义 | 主色 | 文字 | 典型落点 | 用量上限 |
|---|---|---|---|---|
| 空闲 / 就绪 | `--muted` | `--muted` | 状态行「就绪」 | 文字，不带底色 |
| 运行中 | `--accent` | `--accent-ink` | 轴点光晕、focus 环 | 轴点 5px + 光晕 |
| 成功 | `--success` | `--success-ink` | 产出卡**左侧 2px 边** | 2px 边 |
| 降级 / 待确认 | `--warn` | `--warn-ink` | 降级 chip、审批倒计时 | chip 底 / 2px 边 |
| 失败 | `--danger` | `--danger-ink` | 错误卡、unread 红点 | 2px 边 / 13px 红点 |
| 次级语义 | `--violet` | `--violet-ink` | diff hunk、md 格式 chip | chip 底 / 行底 |

**上限的判定方式**（可机械检查）：

1. 实色主色背景元素**边长 ≤64px**。
2. `var(--accent)` 在代码中的**引用处数 ≤60**（2026-10-22 实测组件区 52 处）。
3. 状态色只落在三类载体：**2px 边 / chip 底 / 状态文字** —— 出现第四类即违规。
4. 整块状态色背景**一律禁止**。

### 3.3 双主题同构要求

**结构不变，只换锚点。** 一套 CSS，两套令牌值。

| 手法 | 暗色（石墨仪器） | 浅色（白瓷仪器） |
|---|---|---|
| 面板分层 | `#181818` → `#202020` → `#242424`（**变亮**表示浮起） | `#f7f7f7` → `#ffffff` → `#fafafa`（**变白**表示浮起） |
| 顶边高光 | `rgba(255,255,255,.07)`（弱） | `rgba(255,255,255,.85)`（强，因为底已经亮） |
| 底部内暗 | `rgba(0,0,0,.42)`（强） | `rgba(18,26,38,.10)`（弱） |
| 网格 | 白 2.0% | 墨 2.0%（浅底不需要更多墨） |
| 主色 | `#4c9aff`（亮蓝，暗底上更跳） | `#1f6feb`（深蓝，白底上更稳） |
| 主色文字 | `#9cc7ff` | `#1557c0` |

> **浅色主题只有一条关键规则**：所有"光"从"加白"改成"加黑"，所有"影"从"加黑"改成"加墨"。这就是 `--fx-lit-*` / `--fx-shade-*` 必须**成对出现**的原因。

**新增令牌的硬要求**：任何新增颜色令牌**必须同时**写进暗色与浅色两套，并同步 `02-令牌规格.md`。只加一套 = 浅色主题缺一环。

### 3.4 对比度底线（实测值，均对 `--surface`）

| 前景 | 暗色 | 浅色 | 要求 |
|---|---|---|---|
| `--text` | 15.17:1 | 17.40:1 | ≥4.5 ✅ |
| `--text-2` | 8.21:1 | 8.72:1 | ≥4.5 ✅ |
| `--muted` | 5.04:1 | 5.33:1 | ≥3.0 ✅ |
| `--accent-ink` | 9.33:1 | 6.65:1 | ≥4.5 ✅ |
| `--danger-ink` | 8.16:1 | 7.96:1 | ≥4.5 ✅ |
| `--success-ink` | 10.10:1 | 6.63:1 | ≥4.5 ✅ |
| `--warn-ink` | 13.27:1 | 7.27:1 | ≥4.5 ✅ |
| `--violet-ink` | 8.81:1 | 8.73:1 | ≥4.5 ✅ |
| `--muted-2` | 2.55:1 | 2.78:1 | ⚠ **禁用/占位级，禁止承载信息** |

> 需要弱化正文时用 `--muted`（5.04:1 / 5.33:1），**不要**下沉到 `--muted-2`，也不要新造三级文字令牌。

### 3.5 品牌例外：π 的颜色

π 是全产品**唯一**允许"比气泡亮"的元素 —— 这是品牌硬规则，不是例外中的例外：

| | 暗色 | 浅色 |
|---|---|---|
| 气泡（accent 釉面） | `--accent` `#4c9aff` → `--accent-2` `#1f6feb` | `#1f6feb` → `#1557c0` |
| π 三段渐变 | `--ball-pi-hi` `#eaf4ff` → `--ball-pi-mid` `#c2dcff` → `--ball-pi-lo` `#93c2f6` | `#ffffff` → `#e2efff` → `#b9d6f7` |

π 最暗端（`--ball-pi-lo`）**必须仍比气泡亮**，否则 π 会从"浮雕"读成"凹洞"。同理 `--ball-ink`（π 的实体色）暗色为 `#0b1220` 深蓝墨、浅色为 `#1557c0` 主色蓝，**禁止改成近黑**。

## 4. 字体与数字

### 4.1 字体栈（零外部资源）

```css
--sans: system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif;
--mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace;
```

**禁止** `@font-face`、外部字体 CDN、图标字体（外部资源 + 零构建约束的硬性要求）。

### 4.2 字号阶梯（已落地实测值）

| 层级 | 字号 | 场景 | 配套 |
|---|---|---|---|
| 分区标题 | **10px** | 大窗列头、抽屉块标题、能力菜单标题 | `font-weight:700` + `letter-spacing:.10em` + 大写；色 `--muted` |
| 状态 / meta | **10px** | 状态行、消息 meta、代码块语言名 | `--mono` + `tabular-nums` + `letter-spacing:.03em`（语言名 `.08em`） |
| 产出卡 meta | **10.5px** | 产出卡副信息 | `--mono` + `tabular-nums` |
| 键值标签 | **11px** | 关于页左列 | `--muted` |
| 等宽正文 | **11.5px** | 关于页版本号、按钮文字、代码块正文 | `--mono`；代码块 `line-height:1.65` |
| diff 行 | **11px** | diff 每行 | `--mono` |
| 小标题 / 用户气泡 | **12px** | 窗口标题、用户消息正文 | 标题 `font-weight:700` + `letter-spacing:.02em` |
| **正文** | **12.5px** | 助手消息正文、输入框 | `line-height:1.6`（正文）/ `1.5`（输入框） |

> **字距只有三档**：分区标题 `.10em`、代码语言名 `.08em`、meta `.03em`。正文 `0`。**不多不少** —— 字距是排印里的"装饰件"，一旦放开就变成风格噪音。

### 4.3 等宽数字的适用范围

| 用等宽 | 理由 |
|---|---|
| 时间戳（消息 meta、状态行） | 每分钟变一次，比例字体会让整列抖 |
| 字节数 / token 数 / 上下文占比 | 读数，需纵向对齐可比 |
| 版本号 | 右对齐列 |
| diff 行号 | 增删行不能让行号列抖（配 `min-width` + 右对齐） |
| 产出卡文件名 / meta | 与 meta 同构 |

> **不用等宽**：普通中文正文、段落、按钮上的汉字。**禁止**在 12.5px 正文里混排等宽数字。

### 4.4 强调的表达方式

正文强调 = **明度提升**（`--text-2` → `--text`），**不是**加粗到 800。`strong` 的存在意义是"这里更重要"，不是"这里更粗"。

## 5. 光影语言

### 5.1 铁律：只允许 inset（透明窗裁剪）

> **为什么 `inset` 安全、`外扩` 危险**：Electron 透明窗的裁切边界 = 窗口矩形。外扩阴影/blur 的**溢出部分落在矩形外的透明区**，在深色壁纸上会显示为一圈**淡方形边** —— 这正是用户投诉两次的现象。而 `inset` 永远落在元素自己的矩形内，**不可能越界**。

**唯一例外**：窗口**内部**的浮层（命令面板、设置面板、toast、popmenu），且距窗口边缘 **≥40px** —— 此时外扩阴影落在**不透明的内容像素**上，不会触及窗口矩形边界。

### 5.2 顶边内高光的语义

```css
box-shadow: inset 0 1px 0 var(--fx-lit-top);
```

| 主题 | 值 | 读作 |
|---|---|---|
| 暗色 | `rgba(255,255,255,.07)` | 上方有一点光擦过顶边 → 面板"被照亮" |
| 浅色 | `rgba(255,255,255,.85)` | 底已经亮了，需要更强的白才读得出"擦亮" |

**落点**：卡片顶边、输入框、浮层顶边、窗口根卡片。
**禁止**：暗色值 >0.12（浅色主题过曝）；用于文字。

> 这是整个方案里**最便宜也最像"仪器"的一笔**：1px、零成本、零外扩，却把所有面板统一成"同一个光源从上方来"。

### 5.3 底部内暗（AO）

```css
box-shadow: inset 0 -8px 14px var(--fx-shade-bottom);
```

暗色 `rgba(0,0,0,.42)`（强）· 浅色 `rgba(18,26,38,.10)`（弱）。作用是让卡片"**坐下去**"而不是"贴上去"。**禁止**改成外扩阴影。

### 5.4 球面光影的层次（品牌锚点）

48px 里体积感的全部来源，**四层基础光影（全部在球内）+ 两个细节层**：

| 层 | 暗色 | 浅色 | 作用 |
|---|---|---|---|
| ① 球面三段径向明度（受光区 34%/28%） | `#5d6a78` → `#2f3945` → `#161c24` → `#090c10` | `#ffffff` → `#e4e9f0` → `#c8d0dc` → `#a3adbd` | 48px 的唯一体积来源 |
| ② 顶部 1px 内高光 | `rgba(255,255,255,.13)` | `rgba(255,255,255,.95)` | 顶边擦亮 |
| ③ 底部 AO 内暗 | `rgba(0,0,0,.45)` | `rgba(78,98,128,.30)` | 球底暗 |
| ④ 底部冷色环境反射 | `rgba(110,150,210,.18)` | `rgba(110,142,196,.22)` | 金属/环境感 |
| ⑤ 镜面高光点 | `rgba(255,255,255,.26)` | `rgba(255,255,255,.9)` | **≤2px**，大于 2px 变脏点 |
| ⑥ 球缘暗角 | `rgba(0,0,0,.55)` | `rgba(88,104,132,.30)` | 与壁纸分离。**禁止改成外阴影** |

> **π 浮凸的实现约束**：π 的"凸"**只靠明度关系**（比气泡亮）+ 一层极小柔影 `0 1px 1.5px var(--ball-logo-shadow)`。**不要**用偏移副本（`::after` 复制一份往下移）做浮凸 —— 48px 下偏移 <1px 贴边、≥1px 分离成重影。

### 5.5 光影的方向性

**全局只有一个光源，且来自左上。** 球面的受光区在 34%/28%，卡片的顶边内高光在顶部，底部 AO 在底部。方向不一致会让界面读起来"歪" —— 这是廉价感最常见的来源。

渐变角度只有三个：**面板头部 `180deg` / 网格线 `0deg`、`90deg` / 轴线 `180deg`**。**不做 45° 斜切。**

## 6. 克制的反模式清单

> 每条都给出**原因**。评审时若有人提某个花活，直接对照本表拒绝。

### 6.1 视觉层

| # | 反模式 | 为什么不做 |
|---|---|---|
| 1 | 球/卡片的外发光、外阴影、彩色描边环 | 落在透明窗的方框角区 = 用户已两次投诉的"球外淡淡的边"；会毁掉"窗口即卡片" |
| 2 | 任何 `transform: scale()` 的 hover/press 反馈 | 窗口裁切 → 缺角。press 用「内阴影加深 + 高光收缩」表达 |
| 3 | 全屏 / 大面积霓虹、赛博紫青渐变 | 彩色面积直接爆表；正文可读性下降；与 3D 球的石墨调冲突 |
| 4 | CRT 扫描线常驻 | 12.5px 正文上的 1px 周期线是持续的视觉噪音 |
| 5 | 噪点/颗粒滤镜（`filter: url(#noise)` 之类） | 需要 SVG filter 资源（违反零外部资源与聊天流零 `<svg>` 约束），且在 11px 等宽字下变脏 |
| 6 | `backdrop-filter` 毛玻璃面板 | 透明窗里透出壁纸 → 配色随用户桌面漂移；滚动时每帧重采样 |
| 7 | 霓虹文字（发光描边的文字） | 正文模糊边缘 = 降低有效对比；小字号下不可读 |
| 8 | 3D 透视倾斜 / `rotateX` 卡片 | 三种几何都破形；需 `preserve-3d`，Electron 透明窗下易出锯齿 |
| 9 | 无限循环的水波/流光背景 | 常驻动画在 Electron 常驻进程里等于常驻 GPU；且会压到正文 |
| 10 | 打字机光标常驻 + 光标闪烁 | 与生成中态脉冲叠噪 |
| 11 | 自定义图标字体 / 图标库 | 外部资源，违反零构建单文件约束 |
| 12 | 在聊天流正文里叠任何纹理 | 12.5px 正文上叠纹理是节拍干扰，直接掉可读性 |

### 6.2 组件层

| # | 反模式 | 为什么不做 |
|---|---|---|
| 13 | 给消息加玻璃拟态底 | 聊天流密度高，磨砂底会毁掉行间网格的可读性 |
| 14 | 给代码块加网格背景 | 11px 等宽字 + 网格 = 摩尔纹 |
| 15 | 让 π 发光 | π 必须读作"浅色实体"，发光会把它变成"光源"而非"浮雕" |
| 16 | 输入区随输入高度动画 | 会推动消息流跳动（跳动比动画更干扰） |
| 17 | 状态色整块底（错误卡整块红） | 彩色面积爆表 |
| 18 | 小窗也放刻度尺 | 360 宽放不下，纯装饰反而挤 |
| 19 | 悬停时整卡提亮 | 提亮会让「hover 的那块」变成本次焦点，破坏明度阶梯 |
| 20 | 用 `filter: blur()` 做标题文字发光 | 小字号发糊 = 有效对比下降 |

### 6.3 网格在小窗的降级（最易踩的一条）

小窗 360 宽里，消息区左右各 12px padding，正文行宽约 336px。**如果网格铺满容器，正文行会坐在网格线上** —— 12.5px 正文 + 1px 网格 = 明显的节拍干扰。

**做法**：网格放在容器 `background-image` 上，正文元素自带底色（消息行本身透明，靠行间间隙露出网格）。
**禁止**：给正文段落加 `background: var(--surface)` 去"压住"网格 —— 那会让聊天流变成一列方块。

## 8. 开发者自查清单

> 提交前逐条过。标注 ⚙ 的可机械检查，其余为人工评审项。

**层级与颜色**

- [ ] ⚙ 组件里没有出现任何 hex / `rgb()` / `rgba()` 字面量；需要透明度用的是 `color-mix(in srgb, var(--x) N%, transparent)`，没有新建 alpha 令牌。
- [ ] ⚙ 本次新增的颜色令牌**同时**写进了暗色与浅色两套，并同步了 `02-令牌规格.md`。
- [ ] 每一处"浮起 / 是子块"都能在 `--surface-*` 阶梯或某一次 `inset` 上找到对应，找不到就是违规。
- [ ] `--surface-3` 没有承载任何正文；`--composer` 没有与 `--surface` 同级使用。
- [ ] 没有任何**整块**状态色背景；状态色只落在 2px 边 / chip 底 / 状态文字三类载体上。
- [ ] 实色主色背景元素边长 **≤64px**；`var(--accent)` 引用处数 **≤60**（现状 52）。
- [ ] `--violet` 没有与 `--accent` 在同一视区做主强调。
- [ ] 弱化文字用的是 `--muted`（5.04:1 / 5.33:1），没有下沉到 `--muted-2`（2.55:1 / 2.78:1）。

**边框与线**

- [ ] 边框只有三级发丝线（`--border` / `--border-strong` / `--fx-edge-hair`），**没有** ≥2px 的描边。
- [ ] `--divider` 与 `--border` 没有混用。
- [ ] 分区标题下的亮线用伪元素渐隐，**没有**和 `border-bottom` 叠成 2px。
- [ ] 短标尺长度在 **18–26px**，不透明度 55–60%，**没有**超过 30px。
- [ ] 消息轴线用 `::after` 绝对定位，**不是** `border-left`（否则正文被挤 1px）。

**光影**

- [ ] ⚙ `.ball` 与窗口根卡片的 `box-shadow` **只有 `inset`**，没有 `drop-shadow` / `text-shadow` / 外扩阴影 / 外发光。
- [ ] ⚙ 组件里 **0 个** `transform: scale()`；hover / press 只改 `border-color` / `background` / `box-shadow(inset)`。
- [ ] `--shadow-1` / `--shadow-2` 只用在窗口**内部浮层**，且该浮层距窗口边缘 **≥40px**。
- [ ] `--fx-glow-*` 只用在距窗口边缘 **≥16px** 的元素上。
- [ ] 顶边内高光统一 `inset 0 1px 0 var(--fx-lit-top)`；暗色值没有 >0.12。
- [ ] 球面光影四层全部在球内；没有用偏移副本做 π 的浮凸。
- [ ] 全局光源方向一致（球受光区在左上，卡片高光在顶部，AO 在底部）；没有 45° 斜切渐变。

**纹理与网格**

- [ ] 网格只铺空白容器；代码块 / diff / 表格 / 正文行正下方**没有**网格。
- [ ] ⚙ `--fx-grid-line` 透明度 ≤0.05，`--fx-grid-size` = 24px（没有 <16px）。
- [ ] 消息行本身是透明的，**没有**给正文加底色去"压住"网格。

**数字与排印**

- [ ] ⚙ 所有读数类数字（时间戳、字节数、token 数、版本号、行号、上下文占比）都用了 `--mono` + `tabular-nums`。
- [ ] diff 行号右对齐且有固定 `min-width`。
- [ ] 正文里没有混排等宽数字；强调用明度提升，**没有**加粗到 800。
- [ ] 字距只有三档（`.10em` / `.08em` / `.03em`），正文是 `0`。
- [ ] ⚙ 没有引入外部字体、图标字体、CDN；图标走 `iconEl()` + CSS `mask-image`。
- [ ] ⚙ 聊天流（`#miniBody`）内**没有**任何 `<svg>` 元素。
- [ ] 状态的表达载体唯一，没有 chip + 边框 + 文案三处重复标注。
